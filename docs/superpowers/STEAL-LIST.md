# Ghost Type — Steal List

Harvested from a 181-tool prior-art sweep (60 in the first pass, 121 in the second).
Ranked, deduped, mapped to milestones. **No code is copied without a malware audit** —
items tagged `code` are ideas-until-audited; see the audit list at the bottom.

_Sweep date: 2026-08-21 · 121 tools in the second pass._

## The gaps that are still ours

Even after 181 tools, nobody does these — they remain Ghost Type's differentiators:

- Nobody personalizes the DELEGATOR's voice — every write-like-me/digital-twin tool in this sweep personalizes what a person writes as an author (emails, blog posts, replies, commit messages); none personalize what a specific owner writes when handing a coding agent its NEXT task. That's a different voice (terse, imperative, context-assuming) that nobody has modeled.
- Nobody lets the owner explicitly opt specific terminals/panes into being driven and visually marks only those — every purple/status-indicator prior art (CodeLooper, tmux-agent-indicator, Ghostty's unfocused-split-fill) tints ALL agent panes automatically or keys off focus, not off an owner-curated allowlist.
- Nobody closes the loop on whether the daemon's own auto-written next-prompt actually worked — skill-extractor's trailing-feedback trick exists for skill-mining, but no tool in this sweep scores a prompt-generator's own output against how the owner reacted in the following session as a continuous training signal.
- Nobody combines fresh-isolated-clone-per-task with persistent cross-session voice/lesson memory — every framework here picks one: disposable-clone agents (Pochi, most orchestrators) have no owner-specific memory that survives the clone, while the memory-carrying tools (gptme, Cursor Automations) run in one persistent workspace, not a fresh clone each time.
- Nobody ships the full stack together: test-gated completion + independently-grounded review + owner-learned-voice prompt generation + an always-on macOS daemon + owner-chosen, visually-distinct terminal panes. Every piece exists in isolation somewhere in this sweep; the combination, especially the last two pieces together, does not.

## Purple-terminal mechanisms (the choose-and-tint UX)

Best concrete, verified mechanisms for "choose which panes + turn them purple":

NATIVE MULTIPLEXER PRIMITIVES (prefer these whenever the driven pane runs under one — no AppleScript, no focus risk):
- tmux: `tmux set-option -p -t <pane-id> window-active-style 'bg=colour53'` (and plain `window-style` for the not-focused look) repaints exactly one pane's real background via the `-p` flag; combine with `window-style` vs `window-active-style` so it auto-fades when the user clicks in. Detect "stopped" via tmux OSC133 hooks (`pane-command-finished`, `pane_command_status` — fires the instant the shell's prompt returns, exit code included, race-free) with `pane-exited`/`pane_dead_status` as the coarse fallback for non-shell-integrated programs. For push-based monitoring of many panes at once, attach with `tmux -CC` (control mode) and consume the `%output`/`%window-add`/state-change stream instead of polling.
- Zellij: single plugin call does both jobs — `set_pane_color(pane_id, Some("#7C3AED"))` to tint, `write_chars_to_pane_id(pane_id, "next prompt\n")` to drive — no focus-juggling, one WASM plugin ABI.
- kitty: one Unix-socket protocol for everything — `kitten @ --to unix:/socket send-text --match id:123 "text"` injects, `kitten @ set-tab-color`/`set-tab-title` on the same matched target tints/labels. The `--match` expression language (id:/title:/cmdline:, boolean AND/OR) is the right model for Ghost Type's own pane-picker UI — "every pane whose title matches gallery-*" declaratively, not click-to-select one at a time.
- WezTerm: `wezterm cli send-text --pane-id <id> "text"` injects independent of focus/visibility; pair with its OSC133 command-zone tracking so `wezterm cli get-text --pane-id --escapes` reads just the last command's output instead of guessing scrollback offsets.

ITERM2 (three redundant, complementary channels — use all three so the signal survives even off-screen):
1. Injection: Python API `session.async_send_text()` targets an exact pane by stable `session_id` (survives Space changes) — skip AppleScript keystrokes entirely.
2. Self-tint from inside the pane, zero external control needed: have the driven CLI (or a thin wrapper Ghost Type launches around Claude Code/Codex) emit `OSC 6;1;bg;red;brightness;N ST` (tab color) or `OSC 1337;SetColors=... ST` (full palette) as plain bytes to its own stdout the moment it starts/stops a task. Works even without Accessibility/AppleScript permissions.
3. Auto-revert for free: model tint as Automatic Profile Switching — push a "ghost-type-active" purple profile when the tracked job becomes foreground in that session, let APS pop it automatically when the job exits (crash, ctrl-c, normal exit all covered without Ghost Type remembering to un-tint).
Also: `OSC 1337;SetBadgeFormat` overlays the current goal text ("gallery: fix thumbnail crop") on the purple pane so color + context land in one glance; Triggers (regex on output -> Run Command / Inject Data / Highlight Line) give an in-terminal fallback completion detector that lives in the profile config rather than the daemon.

GHOSTTY: `unfocused-split-fill`/`unfocused-split-opacity` prove the GPU renderer already draws a per-pane colored overlay keyed on a state flag (today: focus, not "agent-active"). This is the concrete evidence for which upstream Ghostty issue/PR to open (it's open-source Zig) to get "force-tint pane X regardless of focus" as first-class support instead of an OSC-escape workaround.

BARE Terminal.app (no multiplexer) FALLBACK:
- Injection: `CGEventPostToPid(pid, event)` posts synthetic keystrokes directly to the target process's event queue — does NOT require the app to be frontmost, unlike AppleScript `System Events keystroke`. This is the direct fix for "typed into the wrong window because focus moved."
- Pane identity: hold an AXUIElement reference via AXSwift (a Swift wrapper around the AX C API) rather than title-string matching — survives Space changes, minimize, window reorder.
- Drawing the actual purple rectangle: JankyBorders' approach — a tiny standalone daemon using private SkyLight/CGS window-server APIs, deliberately avoiding the Accessibility API for speed and to skip its permission prompt. `borders` re-invocation live-updates an already-running instance's color with no restart. Worth porting its technique directly (code, needs malware audit before copying).
- Reference implementation for "pin to a resolved window_id and deliver without stealing foreground focus": Peekaboo (steipete) — study its background-delivery mechanism as the template for this fallback path.

FOR BACKGROUND (non-visible) PANES: don't drive a GUI pane at all. Spawn the coding agent under a pty Ghost Type owns directly — node-pty (Node) or portable-pty (Rust, what WezTerm's own mux server runs on) — and write the next prompt straight to the master fd. Zero focus/keystroke risk; reserve real GUI automation only for the panes the owner actually wants visible/purple.

CLOSEST FULL PRODUCT ANALOG: CodeLooper (steipete) — per-window colored status badge (green=working/red=stopped) + auto-resume-on-stall, using AX-tree polling or JS-hook injection as dual detection channels. tmux-agent-indicator independently validates hooking Claude Code's own lifecycle events (prompt-submit/permission-request/completion) over polling, and its three-redundant-channel design (border + title + status-bar icon) is worth matching so the signal survives when the owner isn't looking directly at that pane.
